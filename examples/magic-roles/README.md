# Isolated real Magic roles diagnostic

This fixture tests the user's *Investigator → Supervisor → fresh Analyzer* role handoff with the local native Manabrew simulator. It performs **one diagnostic game**, not a measurement study or a CP3/CP4 funding comparison. It neither selects decks nor draws a deck-quality recommendation. It stops at the Analyzer's reviewed draft awaiting explicit approval. It does not publish research, retire evidence, install a runtime, or automatically start Fixer; Fixer is configured and frozen for provenance but is not routed; it is a separately requested repair scope.

The checked-in workflow references generated profiles and inputs and is not executable until `prepare.py` creates the isolated project. `prepare.py` reads the current Magic checkout **without modifying it**, copies the requested role TOMLs' exact source text and applicable project-intent/gate excerpts into four self-contained adapted profiles, records SHA-256 provenance, and configures each role's actual model and effort. Those adapted profiles clearly label historical dispatch/scheduler instructions as source evidence rather than conflicting live authority. The caller's explicitly bounded diagnostic overrides only role self-dispatch, scheduling and production finalization; substantive role boundaries remain. Simon Says starts independent provider processes and records their native thread IDs. Whether those sessions appear as separate Desktop UI chats is unverified. It does not perform a finite check-in schedule or prove compliance with that production process. Do not use this diagnostic as a production study.

Prerequisites: macOS, Simon Says, authenticated Codex access to the models configured in the source TOMLs, an isolated native runtime prepared with `examples/magic-native/prepare_isolated.py`, and the four corresponding deck/GUIDE copies under that runtime. Source profiles currently name Investigator `gpt-6.1-terra/xhigh`, Supervisor `gpt-6-luna/high`, Analyzer `gpt-6.1-sol/high`, and Fixer `gpt-6.1-terra/high`; preparation reads the actual source values and never silently substitutes a model.

```sh
python3 examples/magic-roles/prepare.py /absolute/path/to/collection_plan /absolute/isolated/runtime /absolute/new/project
SIMON_MAGIC_RUNTIME_ROOT=/absolute/isolated/runtime \
  simon-says run /absolute/new/project/workflow.toml --project /absolute/new/project \
  --run-dir /absolute/new/run --context /absolute/new/project/original-task.txt
simon-says status /absolute/new/run
```

The workflow declares the tracked role profiles, instructions, schemas, original question, config, verifier/helpers and all deck/GUIDE inputs as `frozen_project_files`; Simon Says binds each to its original Git blob and mode. Preparation also freezes a manifest of the isolated runtime launcher, complete Python source set, and runtime receipt. Each invocation checks the exact set and hashes, copies verified Python source into action scratch, and uses a fresh private bytecode cache; the native runtime verifies the engine binary and archive against its receipt. The user question, plan/config hash, collection/issue inventory and analysis are tracked stage outputs. The Supervisor executes the native helper once; its output does not present deck-performance analysis. The deterministic verifier calls the unchanged native verification tool, checks the exact candidate and records mechanical findings; it does not certify a model's domain judgment. The Analyzer independently invokes the native verifier against original evidence and must explicitly state that one game cannot justify a deck recommendation or certify rules. A semantic blocker never automatically retries a game: the fixture's Unblocker stops. Raw evidence stays in action scratch. The user must inspect the Analyzer draft and explicitly approve its exact commit, digest and unique approval ID if they choose; even then this fixture merely completes its diagnostic and does not perform publication, deletion or production finalization.

An earlier action guard prohibited setuid `/bin/ps`; that guard has been removed. As in `examples/magic-native`, this fixture retains a narrow compatibility shim that uses `libproc` for same-user process start identity and reports an empty Java host observation only when unprivileged `pgrep` reports no visible Java process; otherwise it stops rather than inventing metrics. A copied SQLite mirror points to original protected attempt evidence so the unchanged native verifier can validate the recorded absolute paths. These compatibility steps do not modify the simulator source or evidence.

Run the local mechanical contract checks without models or games with `python3 -B -m unittest discover -s examples/magic-roles -p 'test_*.py' -v`. These tests use real Git fixtures but do not prove provider compatibility or actual simulation.
