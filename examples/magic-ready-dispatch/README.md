# Direct controller-supervised native collection

This workflow variant keeps the user's configured Investigator, Supervisor, Analyzer and Fixer roles, while moving the long-running native game collection into an authored deterministic command stage. Supervisor independently reviews the Investigator design and commits a structured plan containing the original question, exact configuration hash, ten-game bound and single-launch/no-retry policy. After the plan's exact-candidate review, the controller invokes the frozen native collector directly under its normal action/process supervision. The collector rechecks the question, design, plan, config hash and bound before it touches the native runtime. The plan is protected as a stage input throughout subsequent stages. Analyzer receives the independently reviewed game evidence and may select the declared Fixer route; later runtime builds, warning triage and a narrowly scoped Origin follow-up are the same bounded workflow-defined mechanisms as in `../magic-ready-origin`.

This split addresses an observed failure in `../magic-ready-origin-run-v1`: the native Supervisor model started a long game helper through its own provider tool, then lost the provider tool-session handle and reported blocked. The native handoff was still marked running, two attempts had terminal receipts and a third had a worker receipt but no terminal receipt. The controller did not rerun the action. On inspection, recorded provider/supervisor/worker PIDs and matching known native processes were absent; this is not proof against all escaped descendants or reversal of external effects. That uncertain partial store and all records remain untouched. This new fixture is a separately scoped run in a new project, new action directories and new native stores, not a reset or replay of the uncertain action.

The authoring contract remains domain-owned. The fixed protocol routes declared roles and stage outcomes, but has no Magic-specific game or Fixer logic. A reported target issue selects a bounded repair route only after evidence review; an observed Origin warning plus separate independently failing actual-card controls may select another authored Fixer. Cancellations, fizzles and insufficient-context events must remain distinct, and the Origin trace/control correlation does not prove the original live warning's exact cause. Remaining unresolved warnings lead to a reviewed triage and durable stop, not a claim of production readiness. Git cannot undo network, database or other external effects, and direct process supervision cannot guarantee control of escaped processes.

```sh
python3 -B examples/magic-ready-dispatch/test_contracts.py -v
python3 -B examples/magic-ready-dispatch/prepare.py /absolute/prepared-game-project /absolute/collection-plan /absolute/new/project
simon-says validate /absolute/new/project/workflow.toml
simon-says run /absolute/new/project/workflow.toml --project /absolute/new/project --run-dir /absolute/new/run --context /absolute/new/project/original-task.txt
```

Preparation snapshots the actual role profile/model/effort settings and requires a clean prepared game project and a new destination. Use `--seed` only for an explicitly bounded separate diagnostic; no silent replacement games or automatic action replay. This experimental diagnostic does not install a runtime, publish results, retire raw evidence, establish scientific independence, or certify general Magic rules. Native builds and games require cached dependencies, authenticated native providers and significant time/disk space.
