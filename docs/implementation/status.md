# Implementation status

This is a working early runtime, **not an accepted v0 release**. See the README for commands, recovery and the same-user trust boundary.

The [observed autonomy gaps](autonomy-gaps.md) document controller and workflow limitations exposed by the interrupted Magic study.

## Implemented

- Direct role-to-role stages may omit Reviewer and Unblocker; the Worker selects declared routes and validated checkpoints advance directly. A blocked action without an Unblocker stops. Independent review remains available where configured.
- Strict versioned TOML loading, named pass routes and optional bounded Worker- or Reviewer-selected routes, reference and path checks, frozen instructions/profiles/schemas and explicitly declared project authority files, and draft-07 JSON Schema compilation and artifact validation. Per-stage `protected_inputs` can pin previously reviewed artifacts against each stage's starting checkpoint.
- A locked durable JSON run record and per-action packet, exact invocation, transport logs, result/failure; `preparing` is persisted before action-specific Git checks and checkout, and `running` before action invocation. Interrupted or failed actions require explicit reset rather than automatic replay.
- Detached worker and review worktrees, full Git object identity and ancestry checks, tracked regular-file artifact checks, separate candidate and accepted commits, and a narrowly verified reset that refuses untracked or ignored files.
- Command, Codex and Claude invocation plans, action envelopes, Worker/Reviewer correction loops, bounded Unblocker routing, configurable role profiles, durable transition limits and reviewed route selection, frozen original task context, optional checkpoint-bound approval gates, and automatic continuation through stages. Codex Workers may opt in to in-memory same-stage session continuation during an uninterrupted controller invocation; the handle is cleared on stage pass and not recovered after restart.
- Workflow-authored role scratch environment bindings place build caches in action-owned directories and record the exact paths before invocation. Explicit `adopt-worker` recovery can revalidate certain already-recorded successful Workers after an ignored-file stop or a legacy nonempty object-report parse stop and send the candidate to independent review without replaying it; it never moves or deletes the unexpected files. A recorded legacy Reviewer stop for echoing its exact candidate can also be rechecked with `adopt-reviewer` without rerunning it. Interrupted adoption checks require explicit reconciliation.
- Two executable examples with the same engine and subprocess/Git tests, including corrections, Worker and Reviewer blocks, invalid schema and identity, process failure, and fresh-process interruption.

## Limitations and remaining acceptance work

- macOS is the supported platform. Simon Says launches actions with the invoking user’s permissions and does not sandbox them. It checks frozen authority, state, candidate commits and declared artifacts when actions return; these checks are not a security boundary against hostile processes. Managed Git commands retain their deadline and output limits.
- Managed worktrees reject untracked and ignored files before advancing while allowing empty ignored directory trees, because such files are absent from the reviewed Git checkpoint; write caches under action scratch. A blocked Worker with dirty tracked changes stops for explicit reset. Unblocker actions run in a read-only-intent checkout; they cannot commit repository repairs. Git cannot undo external effects. Operators must confirm action processes and descendants have exited before reset; escaped process groups cannot be verified. Action stdout and stderr are checked against a 64 MiB per-stream limit; exceeding it triggers an attempt to stop the owned process group and leaves the action uncertain. The polling limit is not a hard filesystem quota, so a fast writer can overshoot it and escaped processes remain outside its control.
- Recovery trusts the local action records within the same-user boundary: coordinated modification of old captured output and outcome records is not cryptographically authenticated. Adoption does not support a Worker resumed from a prior provider session because its session provenance cannot be independently reconstructed. See the [authoring guide](authoring-guide.md) before reconciling an interrupted action.
- Reviewer/Unblocker worktrees are retained by default; an explicit completed-run cleanup verifies them before removal. Interrupted review preparation can leave an orphan review directory with no recorded ownership; it is retained and requires manual reconciliation. Interrupted initialization records source identity and baseline; `recover-init` resumes a reservation or explicitly adopts a verified checkout. Legacy null-intent or unsafe partial registrations require manual reconciliation. Older runs without recorded checkout/admin/source/common filesystem identities fail closed for checkout operations and reset; old review packets without ownership records cannot be cleaned automatically. Actions have bounded role-configurable timeouts; an interactive cancellation command is not implemented.
- Schema support is draft-07 without references; selected later-draft keywords are conservatively rejected. JSON Schema verifies structure, not domain correctness.
- Checkpoint validation rejects submodules and non-UTF-8 tracked paths. It hashes tracked content using trusted Git clean filters; filters can cause external effects even when Git times out. Git preflight occurs before a run record is created, while checkout and action Git checks persist initializing, preparing or running state before potentially uncertain effects.
- Codex and Claude have been exercised with native provider invocations. Claude Worker uses Orchestrate-style provider-native defaults, without a Simon Says wrapper or nesting preflight. Refer to [evidence](evidence.md) for the exact configurations tested; other provider settings are not implied by those tests.
- The synthetic opening-hand example is not the real Magic simulator. The real simulator has also run in isolated diagnostics, including bounded ten-game batches and controller-dispatched repairs; remaining warnings and the limits of those observations are recorded in the [dynamic-game example](../../examples/magic-dynamic-game/README.md) and [direct-dispatch example](../../examples/magic-ready-dispatch/README.md). These diagnostics do not establish general simulation quality.

After removal of the action sandbox, `cargo test --all-targets` passed 191 tests with one native integration test ignored; `cargo fmt --check` and `cargo clippy --all-targets -- -D warnings` also passed. Live provider and simulator evidence remains separate from these tests.

## Reference baseline

Orchestrate `281af897fcba59a4ef9476c2ce7aa40ed025b6ed` has an engineering-specific Build controller and a reusable provider seam; this repository adapts provider patterns without modifying Build. `cargo test -p orchestrate-build -p orchestrate-core` passed 48 tests. `cargo test --workspace` failed three CLI architecture tests concerning skill directories. Control Tower `cargo test --workspace` passed once, while a concurrent run and isolated rerun timed out in `web::tests::sse_shows_mutation_output_while_the_later_verifier_is_running`; the cause was not established. Reference checkouts were left clean.

A bounded local Codex session-continuation smoke passed, including one reviewer correction and explicit thread identity; it does not establish broad provider compatibility or cost savings. The local opt-out comparison used fewer reported input tokens in this single fixed-order pair. See [evidence](evidence.md).
